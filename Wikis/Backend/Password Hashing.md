# مستندات الگوریتم هش پسورد (Password Hashing)

**تاریخ:** 2025-12-08
**بخش:** Backend

---

## مقدمه
در سیستم TaskQuest، برای حفظ امنیت کاربران، کلمه عبور (Password) به صورت متن ساده (Plain Text) در دیتابیس ذخیره نمی‌شود. در عوض، از یک الگوریتم هشینگ (Hashing) برای تبدیل کلمه عبور به یک رشته غیرقابل بازگشت استفاده می‌شود.

## الگوریتم مورد استفاده
الگوریتم مورد استفاده در این پروژه **SHA-256** (Secure Hash Algorithm 256-bit) است. این الگوریتم یک تابع درهم‌ساز کریپتوگرافیک است که ورودی با طول دلخواه را به یک خروجی با طول ثابت (256 بیت) تبدیل می‌کند.

### مشخصات فنی
- **ورودی:** رشته متنی کلمه عبور (Password)
- **انکودینگ ورودی:** UTF-8
- **خروجی:** رشته هگزادسیمال (Hexadecimal String) با حروف کوچک
- **طول خروجی:** 64 کاراکتر (هر کاراکتر هگز نماینده 4 بیت است، بنابراین 64 × 4 = 256 بیت)
- **Salt:** در حال حاضر از Salt استفاده نمی‌شود (هشینگ ساده).

## نحوه پیاده‌سازی (C# Code)

متد `HashPassword` در فایل‌های `SignUp.aspx.cs` و `Login.aspx.cs` به صورت زیر پیاده‌سازی شده است:

```csharp
private string HashPassword(string password)
{
    // استفاده از الگوریتم SHA256
    using (SHA256 sha256 = SHA256.Create())
    {
        // تبدیل کلمه عبور به آرایه بایت با انکودینگ UTF-8
        byte[] bytes = sha256.ComputeHash(Encoding.UTF8.GetBytes(password));
        
        // تبدیل بایت‌های هش شده به رشته هگزادسیمال
        StringBuilder builder = new StringBuilder();
        for (int i = 0; i < bytes.Length; i++)
        {
            builder.Append(bytes[i].ToString("x2")); // فرمت x2 برای حروف کوچک هگز
        }
        return builder.ToString();
    }
}
```

## فرآیند ذخیره‌سازی و احراز هویت

### 1. ثبت نام (Sign Up)
هنگامی که کاربر ثبت‌نام می‌کند:
1.  کلمه عبور وارد شده توسط متد `HashPassword` هش می‌شود.
2.  رشته هش شده در ستون `PasswordHash` در جدول `Users` دیتابیس ذخیره می‌شود.

### 2. ورود (Login)
هنگامی که کاربر قصد ورود دارد:
1.  کلمه عبور وارد شده توسط کاربر دوباره با همان متد `HashPassword` هش می‌شود.
2.  هش تولید شده با مقدار ذخیره شده در دیتابیس (ستون `PasswordHash`) مقایسه می‌شود.
3.  اگر دو مقدار برابر باشند، احراز هویت موفقیت‌آمیز است.

## امنیت و ملاحظات
در حال حاضر از Salt (نمک) در فرآیند هشینگ استفاده نمی‌شود. این بدین معناست که اگر دو کاربر کلمه عبور یکسانی داشته باشند، هش ذخیره شده در دیتابیس برای هر دو یکسان خواهد بود. برای افزایش امنیت در نسخه‌های آتی، پیشنهاد می‌شود از Salt تصادفی برای هر کاربر استفاده شود تا در برابر حملات Rainbow Table مقاوم‌تر شود.
